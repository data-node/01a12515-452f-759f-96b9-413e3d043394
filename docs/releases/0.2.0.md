# Notch 0.2.0 — a more useful personal space

Version 0.1.0 remains frozen at its original tag, source, executable and checksum. This release expands the control panel while retaining the small space gray capture notch, local SQLite storage and equal Anthropic/Ollama support.

## New in this release

- Edit title, locator, description, tags and folder/file type. AI preserves user-written titles.
- Archive, recoverable trash, Undo and restore. Your original links and files are untouched.
- Persistent named searches including filters, collection and sort order.
- Query operators: `type:folder`, `tag:ai`, `tag:"team work"`, `is:favorite`, `status:error`.
- Ctrl+Shift+P command palette with arrow-key navigation, filtered commands and saved searches.
- Connected items with explicit shared-tag or compatible-vector reasons.
- Indexing progress counts, issue filtering and retry of failed indexing.
- Pre-upgrade SQLite backup, transactional schema migration, V1/V2 import compatibility and fuller JSON exports.
- Version displayed from package metadata, plus a 70-item prioritized product roadmap with primary-source research.

## Upgrading and recovery

Quit the previous Notch instance before launching this version. The same packaged-app data directory is used. An existing version-1 SQLite library receives a pre-migration backup named `notch.sqlite.pre-v2-<timestamp>.bak` next to the live database. Save your own JSON export too if you want an additional portable copy.

Never point frozen v0.1.0 at an upgraded library. To return to that release, quit all instances and restore the pre-upgrade backup into a separate data directory. Keep the current database and its WAL/SHM files together as a recovery copy. V0.2.0 exports use format version 2; old v0.1.0 cannot import those exports.

## Downloads and validation

Windows x64 portable application and installer are built in GitHub Actions, with SHA-256 files. Tagged releases publish downloadable assets only after the packaged Windows capture/search smoke check passes. Linux can also cross-build the portable executable; such a build is labeled in its download notes and does not establish Windows runtime behavior.

The current build is unsigned. The Windows installer installation/uninstallation flow and provider connections with real user credentials require their own validation. Provider unit tests use mocked responses. Research includes live Onyx/Raycast YC profiles and product websites, Khoj, and official repositories. The unresolved “3rd brain” identification and source limitations are documented in the roadmap.

Validation completed: 25 real SQLite/mocked-provider tests passed on Linux and Windows, nine browser UI tests passed, and native smoke checks passed on both Linux and the packaged Windows runtime. The tagged release workflow passed before publication. Full public portable/installer downloads were verified against their SHA-256 files and GitHub digests; see [validation evidence](https://github.com/data-node/01a12515-452f-759f-96b9-413e3d043394/blob/main/docs/validation.md).
